# Qwen3.5-9B 在 AgentX 重建输入上的持久推理缓存无损压缩初步结果

> **2026-10-04 勘误（v1 复盘）**，以下 v1 内容保留原样供追溯：
> 1. “块大小影响”不成立：byte-lane K/V 的 payload-only 压缩比在 64 KiB 与 256 KiB 下为 1.4857 vs 1.4862，差别来自每块概率表（1 KiB/lane）与约 460 B 的 JSON header。
> 2. “完整持久状态 1.20×”依赖上下文长度（固定大小的 state 与随长度增长的 K/V 混合），不能作为模型属性。
> 3. headline 使用了 raw-byte ANS（≈zstd）；8K 样本的最佳配置为 byte-lane ANS，K/V 1.465×（payload-only 1.486×）。
> 4. 只覆盖每个会话 1 个请求的前 2K/8K token，没有按轮信息；三个会话的结果几乎相同，说明这里测到的是 BF16 字节分布，而不是 agentic 特性。
> v2 按轮实验见周计划“v2 范围变更”，结果将作为本报告的 v2 部分另行给出。

## 结论摘要

本周在一张 RTX A6000 上跑通了 `Qwen/Qwen3.5-9B` 的真实前向 → 混合持久状态提取 → 实际 ANS 编码 → 解码 → 逐字节恢复闭环。模型不是全层 K/V：运行时确认 8 层 full attention 保存 K/V，24 层 linear attention 保存 convolution state 与 recurrent state。K/V 和 convolution state 为 BF16，recurrent state 为 FP32；实验没有做 dtype 转换。

主 M2 样本覆盖三个不同请求、三个 AgentX 会话：8K、2K、2K。256 KiB raw-byte ANS 聚合结果为：

| 口径 | raw bytes | compressed total bytes | raw/compressed | 空间节省 |
|---|---:|---:|---:|---:|
| KV-only | 402,653,184 | 317,701,308 | 1.2674× | 21.10% |
| 完整持久状态 | 558,366,720 | 463,477,144 | 1.2047× | 16.99% |
| FP32 recurrent state | 150,994,944 | 141,960,968 | 1.0636× | 5.98% |
| BF16 convolution state | 4,718,592 | 3,814,868 | 1.2369× | 19.15% |

所有压缩数字包含实际 ANS payload、每流 256-entry 概率表、block header、状态恢复元数据和 archive framing。没有用理论熵或 zstd 冒充 ANS。

## 数据身份与输入构造

- 数据：`semianalysisai/cc-traces-weka-062126@23f152f6f0f9399a85901b89a6458def0ef16729`。
- AIPerf：0.13.0，coding corpus，官方 hash-ID token synthesis。
- 数据集公开 trace 没有原始 Claude payload 或 KV；本报告只代表 Qwen3.5-9B 对确定性 AgentX 合成输入的结果。
- Hugging Face Arrow 会为 union request 补充其他分支的 null 字段，而 AIPerf 的严格 `WekaTrace` schema 拒绝它们。薄适配层只递归删除值为 null 的填充字段；非空未知字段仍然报错。
- 输入直接使用官方合成得到的目标 tokenizer token IDs，避免 decode/re-tokenize 漂移；没有额外套 chat template。全部样本标为 `AgentX-prefix-sampled`。
- M2 请求：trace `002001…/main/1` 取 position-0 的 8,192 tokens；trace `006c98…/main/1` 与 `00ca01…/main/1` 各取 2,048 tokens。跨会话 `hash_id_scope=local`，不做跨会话 prefix 去重。
- M1 的 2K 请求是 M2a 8K 请求的前缀，只用于闭环验收，不重复计入三会话聚合。

## 环境与真实缓存结构

- 模型 revision：`c202236235762e1c871ad0ccb60c8ee5ba337b9a`。
- Python 3.11.16；PyTorch 2.11.0+cu128；Transformers 5.17.0；constriction 0.5.0；zstandard 0.25.0。
- 设备：物理 GPU 1，RTX A6000 48 GB；batch=1；SDPA full attention。
- FLA 与 causal-conv1d 未安装。Transformers 的参考 PyTorch 路径在 8K 仍只需约 2.20 秒前向、峰值约 20.29 GB，因此没有触发安装加速依赖的阈值。

缓存审计结果：

| 状态 | 层数/记录数 | dtype | shape/层 | 2K 总字节 | 8K 总字节 |
|---|---:|---|---|---:|---:|
| key | 8 | BF16 | `[1,4,T,256]` | 33,554,432 | 134,217,728 |
| value | 8 | BF16 | `[1,4,T,256]` | 33,554,432 | 134,217,728 |
| recurrent | 24 | FP32 | `[1,32,128,128]` | 50,331,648 | 50,331,648 |
| convolution | 24 | BF16 | `[1,8192,4]` | 1,572,864 | 1,572,864 |
| complete | 64 | mixed | — | 119,013,376 | 320,339,968 |

这验证了不能把 Qwen3.5-9B 当成“32 层 BF16 KV”。recurrent/convolution 是固定大小的终态持久状态，不被伪装成逐 token prefix。

## M1 正确性闭环

Run：`20261004_m1_qwen35_2k_ansraw`。

- 2,048-token 真实前向产生 64 个持久 tensor，共 119,013,376 bytes。
- 256 KiB raw-byte ANS 产生 472 个有效块；472/472 逐字节相等。
- KV-only 压缩比 1.2673×；完整持久状态 1.1721×。
- 解码 tensor 重建到新的 `DynamicCache` 后，64 个状态全部逐字节一致。
- 使用原缓存和解码缓存继续相同的一个 token，hidden state 完全相等，最大绝对差为 0。

## M2 codec 与块大小对照

8K 主样本 run：`20261004_m2a_qwen35_8k_allcodecs`。全部 18,384 个 codec/block 实例 bit-exact。

| codec | block | KV-only | 完整持久状态 |
|---|---:|---:|---:|
| byte-lane ANS | 64 KiB | 1.4042× | 1.3431× |
| byte-lane ANS | 256 KiB | **1.4650×** | **1.4042×** |
| raw-byte ANS | 64 KiB | 1.2413× | 1.2065× |
| raw-byte ANS | 256 KiB | 1.2675× | 1.2302× |
| zstd level 3 | 64 KiB | 1.2599× | 1.2235× |
| zstd level 3 | 256 KiB | 1.2678× | 1.2307× |

Byte-lane ANS 按实际元素宽度建模：BF16 两路，FP32 四路。它在这个 8K 样本上明显优于 raw-byte ANS；但这是单一模型、单个 8K 请求，不能外推成一般结论。完整状态比 KV-only 难压的主要原因是 FP32 recurrent state：在 256 KiB byte-lane ANS 下 recurrent 为 1.1501×，而 KV-only 为 1.4650×。

## 局限与下一步

- 只有一个模型、三个 AgentX-prefix-sampled 请求；不是原始 Claude 内容，也不是完整 AgentX replay。
- 8K 的 codec 矩阵只来自一个请求；另外两个会话只测 raw-byte ANS。
- 没有对真实文本/代码内容、其他模型、原生低精度 cache 或 16K/32K 做代表性验证。
- 没有测在线 codec 吞吐、TTFT、offload、冷缓存命中率或系统加速。
- 本轮每个会话只纳入一个 M2 请求，因此没有多轮 unique-prefix/suffix 结论；终态 recurrent/convolution 本来也不能按 token span 切分。
- 初步证据支持下一周优先验证输入内容代表性，并复核 byte-lane 收益能否跨请求保持；不据此自动开展低比特权重、多模型扫描或 AMD 优化。
