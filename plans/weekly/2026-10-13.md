## 本周研究问题

v2 在两个 Qwen 模型上得到：去重收益远大于熵编码；BF16 K/V 熵编码约 1.48×，FP8 约 1.20×，并且这是模型数值的固有属性。本周要回答：

1. **这个结论在多大范围内成立？** 换成其他持久状态（MLA latent 与 RoPE key、Mamba2 SSM state、短卷积 state、滑窗 K/V）和其他模型家族、规模时，压缩率分别是多少？
2. **部署时常用的 K/V 量化格式（FP8 的不同变体、INT8、INT4、NVFP4）之后，还剩多少无损压缩空间？** 量化本身是有损的，只作为“被编码的表示”来测，并与 BF16 基线对比有效 bit/元素。
3. **不同数据来源的会话结构（复用率、每轮增量、时间间隔、跨会话共享）差别多大？** AgentX 之外，再看真实生产 trace（TraceLab、Mooncake）、生成轨迹和普通对话。

## 本周范围与非目标

**持久状态类型**（由模型决定；每个新模型先 audit，以运行时事实为准）：

| 状态类型 | 每 token / 固定大小 | 代表模型（单卡 A6000 候选） | 说明 |
|---|---|---|---|
| GQA K/V | 每 token | Qwen3 1.7B / 8B / 14B；Llama-3.1-8B（gated，可选） | 规模和家族对照；已有 Qwen3-4B、Qwen3.5-9B |
| MLA latent `c_KV` + 解耦 RoPE key `k_pe` | 每 token（单“头”，512 + 64 维） | DeepSeek-V2-Lite-Chat；Moonlight-16B-A3B（可选） | transformers 5.17 的 DeepSeek-V2/V3 缓存里存的就是过 `kv_a_layernorm` 的 latent 和加过 RoPE 的 `k_pe`，与 vLLM/SGLang 一致；两者作为两种状态分别统计 |
| Mamba2 SSM state + conv state | 固定大小 | NVIDIA-Nemotron-Nano-9B-v2 / Nemotron-H；Granite-4.0-H-Micro/Tiny；Falcon-H1-7B（并行混合） | 与已测的 Gated DeltaNet（Qwen3.5）对照；state dtype 以 audit 为准 |
| 短卷积 state | 固定大小 | LFM2-2.6B | 只有 conv、没有 recurrent 的混合架构 |
| 滑窗 K/V | 固定窗口 | Gemma-3-12B-it（gated，5:1 局部/全局，窗口 1024） | 只保留最近窗口；按“每轮一份窗口快照”计费（与线性 state 的策略假设相同） |
| DSA indexer key | 每 token | DeepSeek-V3.2 / GLM-5 一类 | 只做登记与微型模型单测；单卡跑不动真实 checkpoint |

不属于持久状态、不测的：RoPE cos/sin 表（可重算）、attention sink（参数）、logits。不在本周范围的其他缓存：多模态编码缓存、投机解码 draft 模型 K/V、LoRA。

**K/V 数据格式**（由部署决定；只作用于每 token 状态：GQA K/V、MLA latent/`k_pe`、滑窗 K/V）：

| 格式 | 被编码的内容 | 备注 |
|---|---|---|
| BF16 | 原生 | 基线 |
| FP8-E4M3，scale = 1 | 1 字节/元素 | v2 已有 |
| FP8-E4M3，每层每张量动态 scale | 数据 + FP32 scale | 对应 vLLM 计算 KV scale 的方式 |
| FP8-E5M2 | 1 字节/元素 | vLLM 支持 |
| INT8 对称量化，每 token 每 head 一个 scale | 数据 + FP16 scale | |
| INT4（KIVI 风格：K 按 channel 分组、V 按 token 分组，组大小 64，非对称） | 打包 nibble + FP16 scale/zero | 需要新增 nibble 编码器 |
| NVFP4（E2M1，每 16 个元素一个 FP8-E4M3 块 scale + FP32 全局 scale） | 打包 nibble + 块 scale | 可选：MXFP4（每 32 个元素，E8M0 scale） |

量化步骤都是**带标注的事后转换，不回灌模型**。无损压缩相对“量化后的表示（数据 + scale 等元数据）”定义；同时报告相对 BF16 的端到端比例和有效 bit/元素；量化误差（相对 L2、余弦）只作参考，不是本项目的结论指标。

**数据**（详见 [`docs/datasets.md`](../../docs/datasets.md)）：

- 结构分析（CPU）：AgentX 完整版全部 393 个会话 + 256k 变体；TraceLab；Mooncake 公开 trace（核实后）；nebius、thoughtworks、SWE-ZERO 各抽样 200 条；ShareGPT 或 WildChat 抽样 200 条作为普通对话对照。
- 前向内容集（GPU），选择规则先于任何压缩结果固定：
  - **短上下文集**（所有模型都跑，≤32K token）：v2 用过的 SWE-agent 轨迹 0 和 3，加 thoughtworks 中前 2 个“≥15 轮且 ≤32K token”的会话。
  - **长上下文集**（只给原生上下文 ≥128K 的模型）：AgentX 256k 变体中与 v2 相同的会话 t1、t2，加留出会话 trace 3 用于校准。

**编码器**：zstd、`ans_lane`（块内表）、`ans_lane_shared`（共享表），只用 64-token 单元（块大小已在 v2 测完）；4-bit 格式另加 nibble 分路编码器。每个模型、每种格式各校准一套共享表。

**资源**：只用 GPU 1，**每条命令前写 `CUDA_VISIBLE_DEVICES=1`**；batch=1；显存警戒 44 GiB；GPU 总预算 ≤14 GPU-h；CPU 编码 16 进程。磁盘：先 `df -h` 和查配额；模型逐个下载、用完可删（记日志）；压缩归档在重建检查通过后可删（记日志），`units.csv.gz` 保留。

**本周明确不做**：编解码吞吐与 GPU ANS、系统集成（vLLM/LMCache/Mooncake）、低比特权重压缩、第二张 GPU、BF16 权重超过约 32 GB 的模型、修改 RoPE / YaRN 来延长上下文、冷 KV 的缓存策略模拟（只做时间间隔统计）。

## 风险与降级

最可能的阻塞：
- gated 模型（Gemma、Llama）需要在 HF 上接受许可并配置 token。token 由用户自己配置，agent 不读取、不打印、不写入文件。
- 下载慢（v2 时未认证下载一个 9B 模型用了约 16 分钟）→ E0/E1 期间提前在后台逐个下载。
- 磁盘：全部候选模型合计远超 v2 的预算 → 一次最多保留 2 个模型。
- 新架构在 HF 里的缓存层类型名不在已审计列表中 → runner 按设计 fail closed，需要逐个补适配。

降级顺序：
1. 去掉 MXFP4、FP8-E5M2；
2. 去掉 Qwen3 规模两端（保留 8B）；
3. 没有许可的 gated 模型直接跳过；
4. 去掉 SWE-ZERO 和普通对话对照；
5. 新模型只跑短上下文集。

无论如何不能放弃的：逐字节无损验证；全部元数据计费；数据与模型的身份记录（revision、选择规则）；事后量化格式的标注；不把量化误差、熵估计或 zstd 结果当作 ANS 实测。
